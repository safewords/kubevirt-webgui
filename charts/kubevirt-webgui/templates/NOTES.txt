{{ .Values.settings.productName }} is installed as {{ include "kubevirt-webgui.fullname" . }}.

Reach it:
{{- if .Values.ingress.enabled }}
{{- range .Values.ingress.hosts }}
  http{{ if $.Values.ingress.tls }}s{{ end }}://{{ .host }}
{{- end }}
{{- else if eq .Values.service.type "LoadBalancer" }}
  kubectl -n {{ .Release.Namespace }} get svc {{ include "kubevirt-webgui.fullname" . }} -w
  (the address appears under EXTERNAL-IP, then open http://<address>:{{ .Values.service.port }})
{{- else }}
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "kubevirt-webgui.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}
  then open http://127.0.0.1:{{ .Values.service.port }}
{{- end }}

Signing in: with your own Kubernetes credentials — a token, or a kubeconfig you
paste in. The server has no privileges of its own, so what you can see and do
is exactly what your RBAC allows, and nothing an install can widen.

  kubectl -n {{ .Release.Namespace }} create token <serviceaccount>   # one way to get a token
